P0-1

Creating an order returns a full-page 500

seat-verifiedcore path · hard failure
Route
/requests/new
What
A normal, well-formed paid order (Starbucks ×2, valid client + email, fake data) returns “This page couldn’t load / A server error occurred” (ERROR 294045514). No order is created. If the walkthrough opens with “let’s make an order,” it dead-ends on a white error page.
Repro
Sign in as redstamp → New Manual Order → fill client/contact/email, Payment status = Paid → add one line item (any card + denomination), qty 2 → Create order → 500. Reproduced by the seat and by Grok (twice); confirmed no orphan order is written.
Likely cause
Server-side create handler. Console also shows an invalid phone pattern regex under the /v flag — a strong candidate. Loci: src/app/requests/new/page.tsx, src/lib/clients/client-form.tsx, and the create server action.
AcceptCreating a paid order via /requests/new succeeds (no 5xx) and the new order appears in /fulfillment. Add a regression test for the create path with a valid + an empty phone field.

↳ lane/fix-create-order-500

P0-2

Walmart activated-result import 500s on file upload

Grok ×2Walmart demo path · hard failure
Route
/requests/PGC-1027 → Walmart Card Preparation step
What
Choosing the blessed 120-row fixture through the file picker returns a full-page 500 (ERROR 777059612). Pasting the same file succeeds (?walmartImported=120). A non-technical operator uses “Choose file,” not paste — and this is the exact new Walmart flow being demoed.
Repro
Open a Walmart order at the Card Preparation step → Choose file → …/sample-files/PGC-1027-walmart-activated-result-120-valid.csv → 500 (POST ?walmartError=input). Same file pasted into the textarea imports 120. Not seat-re-run (would mutate shared staging); corroborated by the seat-verified sibling 500 which uses the identical error page.
Likely cause
The file-upload branch diverges from the paste branch and hits an unhandled parse/validation path. Loci: src/lib/walmart-preparation.ts, src/app/requests/[requestNumber]/walmart-preparation/route.ts, walmart-result-import-form.tsx. Worth checking whether the 500 masks a DoS/malformed-input path.
AcceptUploading the fixture via the file picker imports 120 cards, identical to the paste path (no 5xx). Add a test feeding the fixture through the upload handler.

↳ lane/fix-walmart-import-fileupload-500

P0-3

Status pill never advances past “Allocated”

3-laneKaitlin commitment unmet
Route
/, /fulfillment, and order headers
What
Orders past allocation (Export created / Download / Customer delivery) still show “Allocated” on the dashboard, orders list, and the order header — while the same order’s own progress bar shows a later step. e.g. PGC-1026: progress on Download, every pill says Allocated. Three workflow states collapse to one label.
Found by
All three lanes independently; two root-caused it to the pill reading only fulfillmentStatus. This is the item reported fixed on 08-12 — it is only half-closed (basic labels are semantic; the pill doesn’t advance).
Fix locus
src/lib/format.ts + the pill selector: derive the furthest current workflow state (Export created / Downloaded / Customer delivery) rather than mapping fulfillmentStatus alone. The two-pills-per-header rule is already correct — keep it.
AcceptAn order at Export/Download/Delivery shows a pill matching its current progress step on the list, dashboard, and header — one consistent story per screen.

↳ lane/status-pill-workflow-state

P0-4

Sidebar hides Integrations + Audit Log at laptop height

seat-verifiednav dead-end
Route
all routes (sidebar)
What
At laptop viewport heights (<≈700px inner height; reproduced at a 1280×800 window / 623px viewport) the pinned “Redstamp Admin” user block covers the Integrations and Audit Log nav links. The nav is overflow-y:hidden, so there is no scroll path. Collapsed icon-rail restores Integrations but Audit Log stays hidden. Two admin screens become unreachable from the nav.
Found by
Claude (DOM-probed via elementFromPoint); the seat then watched both links vanish from the sidebar live at 1280×623.
Fix locus
Make the nav list scrollable or put the user block in normal flow so it can’t occlude links. Also test the actual walkthrough laptop’s viewport height — this is height-dependent.
AcceptAt 1280×800 every sidebar link — including Integrations and Audit Log — is visible and clickable in both expanded and collapsed modes.

data looks wrong
Route

What
