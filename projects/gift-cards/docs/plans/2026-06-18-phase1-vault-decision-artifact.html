The reframe

Three directions, one model

The discovery instinct was "23 merchants, ~23 formats — how many do we hardcode?" The data and Progressive's own team both say that's the wrong axis. We arrived at the same answer from three directions — which is the headline for the call: we're formalizing what your operator already does, not proposing something new.

Lloyd · operator

Data is "inhomogeneous by supplier, not merchant." Only Amazon, Walmart, Chapters-Indigo truly generate cards; the rest are pass-through. Adding a merchant "shouldn't require a software change."

James · their counsel

Pushing Doug toward a general system over targeted merchants — on the grounds that merchants share import structure.

Redstamp · the data

Profiling the real redstamp.zip files collapses 23 merchants into ~7 supplier families. Two with identical schemas only looked different by filename.

The model

Normalize on ingest, store canonically, output by rule

Every card becomes one internal record. The only thing that really varies between merchants is the redemption payload — and even that reduces to a single shape: an optional URL plus a typed bag of secrets.

// one shape covers every merchant credential = { url?: string // redemption / claim link secrets[]: { type, value } // type ∈ claim_code · card_number · pin · challenge · account_number · security_code instructions?: string // per-merchant redemption steps }

Output is a rule on that record, in one of two modes — and Lloyd's point is the same brand can go out either way, so it's an order setting, not fixed by merchant:

MODE A

Repackage

Existing credentials → password-protected customer file. The pass-through majority.

MODE B

Generate

Render a PDF card from the credential → ZIP. Amazon; per Doug also Walmart & Chapters-Indigo.

WALMART

Bidirectional

The one externally-fixed output: produce Walmart/Fiserv's expected work file, import activated results back.

Findings vs SOW

The judgment call (Spencer + Tim): the architecture is general, but the fee must stay bounded. "Add a merchant inside a known family = configuration (no charge); brand-new supplier shape = CO" gives Lloyd his ask and protects the fee.
